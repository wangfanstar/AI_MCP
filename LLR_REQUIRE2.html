📌 核心改进点
前导码识别 标准帧使用标准IEEE前导码（Bytes 1-3 = 0x55 0x55 0x55），LLR-eligible帧在Byte 1的D[3:0]设置为0x7，Bytes 1-3包含20-bit帧序列号frame_seq[19:0]
PCS编码层 LLR前导码映射到64B/66B Block Type 0x78，编码器必须识别D1[3:0]=0x7以区分LLR-eligible帧
MAC层处理 MAC必须从接收的前导码中提取frame_seq，并通过llr_field接口向LLR传递；发送时分配和编码frame_seq
序列号宽度 20-bit序列号允许在800Gbit/s速率下支持>500µs的RTT，支持最多1,048,575个未确认帧
🎯 必需模块适配：
  • MAC发送端：LLR-eligible帧分配frame_seq并编码到前导码
  • MAC接收端：从前导码提取frame_seq，关联到LLR处理
  • PCS编码器：识别Block Type 0x78中的D1[3:0]=0x7
  • RS层接口：MII传输frame_seq和preamble信息
  • Replay Buffer：存储LLR-eligible帧按sequence号索引

📌 核心改进点
CtlOS报文结构 8字节控制消息，MII Layer 0使用0x5C控制字符区分于IDLE的0x9C，D1字段编码消息类型（0x01/0x02/0x03/0x04），D2-D4[7:4]含20-bit序列号，D4[3:0]固定为0x6
PCS编码改进 MII 0x5C映射到64B/66B Block Type 0x4B，O-code值0x6是关键区分标志（vs Sequence的0x0），需要支持无状态编码规则以支持CtlOS在数据包中间的插入
插入约束 CtlOS必须8字节对齐、不能在帧前256字节内、两个CtlOS间距≥400字节（最多占用2%链路带宽），这些规则确保交换机正确处理
优先级机制 LLR_INIT_ECHO优先级最高以确保初始化，LLR_INIT次之，ACK/NACK优先级最低，如果启用CBFC，CF_Update优先级在ACK/NACK之下
🎯 必需模块适配：
  • MAC层：管理CtlOS生成请求，验证插入约束（间距、位置），调用RS接口
  • RS发送端：在MII上输出Lane 0=0x5C和对应的D1-D7数据，保证8字节对齐
  • PCS编码器：识别0x5C并映射到Block Type 0x4B，O-code设置为0x6，实现无状态编码规则
  • RS接收端：识别Lane 0=0x5C且RXC[0]=1的CtlOS，通过MA_CONTROL.indication转发
  • LLR状态机：处理4种CtlOS类型，触发状态转换（INIT→ADVANCE→REPLAY等）

📌 核心改进点
TX状态机 INIT(初始化)→ADVANCE(正常发送)→REPLAY(重传)→FLUSH(清空)，状态转换由init_echo_received、nack_received、replay_timer_expired和PCS_lost_status等条件控制，支持多次重传尝试配置
Replay Buffer 按frame_seq索引存储LLR-eligible帧，大小受带宽延迟积限制（防止PFC失效），ACK接收时按最新ack_seq释放空间，FLUSH状态时清空所有内容，不允许对帧进行截断
RX端序列检查 维护next_rx_seq期望序列号，对乱序帧（missed or duplicated）立即发NACK并拒收，FCS验证GOOD/POISONED送ACK，BAD时标记frame_bad但不触发重传
计时器和计数 replay_timer用于超时触发重传（可配置重试次数replay_ct_max），ctlos_spacing控制ACK/NACK周期，data_age_timer判定数据过期，outstanding_seq/data计数管理未确认资源
🎯 必需模块适配：
  • LLR TX状态机：实现5-state FSM(OFF/INIT/ADVANCE/REPLAY/FLUSH)，完整的状态转换逻辑和条件评估
  • Replay Buffer管理：数据结构存储LLR帧，索引和检索，ACK处理时的段释放逻辑
  • ACK/NACK FSM：独立的ACK/NACK发送状态机(OFF/SEND_ACKS/SEND_NACK/NACK_SENT)
  • 计时器驱动：replay_timer、data_age_timer实现，中断驱动或轮询
  • RX序列验证：LLR-eligible帧的序列号检查和FCS状态评估
  • 统计计数器：tx_seq、next_rx_seq、replay_ct、outstanding等变量管理
  • CBFC交互：在REPLAY/DISCARD窗口中正确处理计数器更新规则

📝 总体模块适配清单

  • MAC层：frame_seq编码/解码、CtlOS生成请求、LLR-eligible帧标记、插入约束验证
  • RS层：MII接口增强、0x5C/0x9C控制字符处理、8字节对齐、llr_field数据通路
  • PCS编码层：Block Type 0x78和0x4B识别、O-code映射、无状态编码规则、preemption支持
  • LLR逻辑层：TX/RX状态机、Replay Buffer、ACK/NACK FSM、计时器、序列号跟踪
  • 物理接口：frame_seq提取、CtlOS插入/检测、MII信号同步
  • 配置和管理：参数寄存器(llr_mode_local/remote、replay_ct_max、ctlos_target_spacing)、计数器统计

🔗 关键链接关系

  • 前导码↔序列号：frame_seq在前导码中编码，通过MAC提取后传给LLR进行Replay Buffer索引
  • CtlOS↔状态机：CtlOS 4种类型对应LLR的不同状态转换和操作（INIT/ADVANCE/REPLAY/FLUSH）
  • 重传↔CBFC：LLR重传过程中需要特殊处理CBFC计数器，避免计数错误导致流控失效
  • 插入约束↔性能：CtlOS 间距和带宽约束确保实时性和低延迟，同时不影响数据包传输效率
