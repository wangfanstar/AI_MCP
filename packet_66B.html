一、以太网帧 → 66B 块流转换（正常报文）

以太网帧经 PCS 64B/66B 编码后变成 66-bit 块流。每个块由 2-bit sync header + 64-bit payload 组成。
• SOP (Start): sync=10, Block Type=0x78, 载荷 = /S/ + Preamble D1..D7
• Data: sync=01, 8字节 MAC 帧数据
• EOP (Terminate): sync=10, Block Type=0x87, Terminate + FCS 残余
• IDLE: sync=10, Block Type=0x1E, IPG 空闲
MAC Client以太网帧: DA + SA + Type + Payload + FCS
LLR 层决定 LLR-eligible / ineligible，附加 frame_seq
PCS 64B/66B编码为 66-bit 块流 (SOP→Data→EOP)
PHY发送到物理链路

三、LLR-ineligible 报文 (标准前导码)

与 IEEE 802.3 标准帧不可区分。Start 块载荷 D1..D7 固定为 55 55 55 55 55 55 D5。

CtlOS 控制有序集（Control Ordered Sets）

CtlOS 使用 66B 块：sync=10, Block Type=0x4B, O-code=0x6。
D1 为消息类型：0x01=ACK, 0x02=NACK, 0x03=INIT, 0x04=INIT_ECHO, 0x10=CF_Update(CBFC)。
序列号 20-bit 编码在 D2(seq[19:12]), D3(seq[11:4]), D4[7:4](seq[3:0])。
INIT/INIT_ECHO 还携带 init_data[15:0] 在 D5(bits[15:8]) 和 D6(bits[7:0])。

链路混合块流演示

真实链路上的 66B 块流是各种块类型的混合：IDLE、CtlOS、SOP(eligible/ineligible)、Data、EOP 交替出现。
CtlOS 可以抢占数据包传输（但不在前 256 字节内），最小间距 ≥ 400B。

异常情况与 LLR 重传机制

当接收端检测到 LLR-eligible 帧的 FCS 错误（BAD）或序列号异常时，发送 LLR_NACK。 发送端收到 NACK 后完成当前帧传输，然后进入 REPLAY 状态，重传 replay buffer 中的帧。
• FCS=POISONED：不触发 NACK（错误传播）
• FCS=BAD + expected seq：触发 NACK → 重传
• 序列号异常（missing/duplicate）：触发 NACK → 重传
