xMII 接口层 — 标准以太网前导码 (8 Bytes)
IEEE 802.3 标准前导码：7 字节 0x55 + 1 字节 SFD (0xD5)。
所有字节为 数据字节（TXC = 0），RS 层不做特殊处理。不携带任何 LLR 元数据。

66-bit Block Structure
Sync Header = 01（标识为纯数据块）。
64-bit payload = 8 字节数据原样映射，无块类型字段，无 O-code。编码开销：66/64 = 3.125%
▼
SerDes 串行化输出
66-bit:
66 位顺序发出，在 100Gb/s/lane 下耗时约 0.66 ns。
xMII 接口层 — UE LLR-Eligible 前导码 (8 Bytes)
UE LLR-Eligible 前导码：携带序列号，帧受 LLR 保护，进入重传缓存。
• Byte 0: 0xFB — Start 控制字符（TXC[0]=1），触发 RS 层识别为帧起始
• Byte 1[3:0]: 0x7 — LLR-eligible 标识码（区分 ineligible 的 0x5）
• Byte 1[7:4] + Byte 2 + Byte 3: 20-bit frame_seq 序列号（0~1,048,575）
• Byte 4-6: 0x55 — 标准前导码填充（保持 CDR 时钟恢复特性）
• Byte 7: 0xD5 — SFD（IEEE 802.3 Start Frame Delimiter）
• 20-bit 空间可覆盖 800Gbps 下 >500μs 的 RTT
▼
PCS 64B/66B 编码 — 起始控制块 (Start Block)
66-bit Block Structure — Block Type 0x78 (Start)
Sync Header = 10（控制块）。Block Type = 0x78（IEEE 标准 Start-of-Frame）。
Payload 中嵌入了 LLR 元数据：0xFB + 0x07 + 20-bit seq，对 PCS 层 透明 — PCS 不解析 LLR 语义。
xMII 接口层 — UE LLR-Ineligible 前导码 (8 Bytes)
UE LLR-Ineligible 前导码：帧不受 LLR 保护，不进入重传缓存，标准以太网处理。
• Byte 0: 0xFB — Start 控制字符
• Byte 1-6: 0x55 — 标准前导码（与标准以太网前导码一致）
• Byte 7: 0xD5 — SFD
• 典型场景：Pause 帧、PFC 帧、CF_Update 等流控信号必须标记为 ineligible，防止重传干扰流控。
▼
PCS 64B/66B 编码 — 起始控制块 (Start Block)
66-bit Block Structure — Block Type 0x78 (Start)
同样映射为 Sync = 10、Block Type = 0x78。
PCS 层 完全无法区分 eligible 与 ineligible — 区分完全由 RS/LLR 层在 xMII 侧根据 Byte 1 的标识码完成。
LLR-Eligible

✅ 可重传帧 — 携带 frame_seq

64B/66B: Block Type 0x78
LLR 行为：分配 tx_seq → 存入 Replay Buffer → 等待 ACK → 超时/NACK 触发重传
LLR-Ineligible

⛔ 不可重传帧 — 无 frame_seq

64B/66B: Block Type 0x78
LLR 行为：不分配序列号 → 不存入 Replay Buffer → 直接透传 → 丢失不触发 NACK
⚡ Eligible vs Ineligible 核心差异：

1. Byte 1[3:0] 标识码：0x7 (eligible) vs 0x5 (ineligible) — RS 层据此决定是否进入 LLR 保护路径
2. 序列号字段：eligible 携带 20-bit frame_seq；ineligible 该字段为 0x00（不分配）
3. 重传缓存：eligible 帧存入 Replay Buffer；ineligible 帧 绕过 重传缓存
4. 64B/66B 编码：两者在 PCS 层 完全相同（均为 Block Type 0x78），差异仅在 xMII payload 语义
5. 典型帧类型：
  • Eligible: 普通数据帧、CBFC Best-Effort 帧
  • Ineligible: Pause 帧、PFC 帧、CF_Update、LLDP 帧
xMII 接口层 — IEEE 序列有序集 (Sequence Ordered Set)
IEEE 802.3 Clause 82 — Sequence OS：
• Lane 0: 0x9C（控制字符，TXC[0]=1）— RS 层识别为序列有序集
• Lane 1-3: 序列号或标识数据
• Lane 4-7: 填充或扩展数据
用于 PCS 层序列号同步和链路状态通告。
▼
PCS 64B/66B 编码 — O-code 控制块
66-bit Block — Block Type 0x4B + O-code 0x0
Sync = 10，Block Type = 0x4B（O-code 型控制块），O-code = 0x0（IEEE 标准序列有序集）。
O-code 0x0 = 0000，这是 IEEE 分配的基准码点。

O-code 0x6 被 UE 选用的原因：
• 与所有已占用码点（0x0, 0x1, 0x4）的 Hamming 距离 ≥ 2 → 单比特翻转安全
• 0x7 虽最安全（HD=3），但被 IEEE 预留给未来标准扩展
xMII 接口层 — UE LLR 控制有序集 (CtlOS)
UE LLR CtlOS — 控制平面信令：
• Lane 0: 0x5C（控制字符，TXC[0]=1）— RS 层一个周期即可判定为 CtlOS
• Lane 1: 消息类型 msgType（见下方表格）
• Lane 2-4: ack_nack_seq / last_good_seq / init_seq (20-bit)
• 带宽占用 < 0.5%（推荐间隔 2048 字节）
▼
PCS 64B/66B 编码 — UE 自定义 O-code 控制块
66-bit Block — Block Type 0x4B + O-code 0x6 (UE LLR)
Sync = 10，Block Type = 0x4B（同 IEEE O-code 块类型），O-code = 0x6（UE 专用码点）。
与 O-code 0x0 的 Hamming 距离 = 2 bits，提供单比特翻转保护。
⚡ 关键：Block Type 沿用 0x4B，意味着 对不支持 LLR 的设备，仅表现为一个未知 O-code 的有序集 — 向后兼容。

⚡ 核心差异总结：

1. xMII Lane 0 控制字符：0x9C vs 0x5C — 不同的字节让 RS 层在 同一个时钟周期 就能区分两种有序集。
2. 64B/66B Block Type：两者都映射到 0x4B — 共享同一种控制块格式（O-code 块）。
3. O-code：0x0 (IEEE) vs 0x6 (UE) — Hamming 距离 = 2，单比特误码不会导致误判。
4. Payload 语义：IEEE 用于 PCS 同步；UE 用于 LLR ACK/NACK/INIT 控制信令。

O-code 0x6 的选择逻辑：
• 与 0x0 (Sequence OS) 的 HD = 2 → 不会因单比特翻转误判为 IEEE 序列有序集
• 与 0x4 (SOP Variant) 的 HD = 2 → 不会误判为帧起始变体
• 0x6 是唯一一个对 所有已占用码点 都保持 HD ≥ 2 的可用值
• 0x7 虽更安全 (HD=3)，但被预留给 IEEE 未来标准扩展

⏱ RS 层解析流水线：0x5C (单周期判定) vs 0x9C 复用方案 (双周期判定)

✅ 方案 A — 独立 0x5C（UE LLR 采用）
T0
Lane 0 接收: 0x5C 识别→ 立即确定为 CtlOS
T1
解析 Lane 1-7: 提取 LLR 信令→ ACK/NACK/seq 数据可用
T2
信令已就绪→ 可送入 LLR 状态机处理
❌ 方案 B — 复用 0x9C（被拒绝方案）
T0
Lane 0 接收: 0x9C 接收→ 无法区分 Seq OS 还是 CtlOS
T1
解析 Lane 1 区分字段: +1 时钟延迟→ 这里才能判定类型
T2
解析剩余数据: 提取信令数据
T3
信令就绪→ 比方案 A 晚 1 个周期
代价量化 @ 100Gb/s per lane：
• 1 个时钟周期 ≈ 0.8 ns （处理 1 字节 @ 100G/lane）
• 对于 8 字节有序集，解析延迟 = 1/8 = 12.5% 的额外开销
• 在多级流水线中，这个气泡会影响后续所有阶段的就绪时间
• 硬件流水线设计铁律：判定越早，代价越小

CtlOS 插入策略（UE Spec v1.0 Section 6.2）：
• 帧起始后 前 256 字节：禁止插入 CtlOS（保护帧头解析）
• 最小间隔：400 字节（强制要求）
• 推荐间隔：2048 字节（带宽占用 < 0.5%）
• CtlOS 使用 Pre-emptive Insertion：暂停数据发送，插入 8 字节 CtlOS 块，然后恢复
• 对上层 透明 — 接收端 RS 层自动剥离 CtlOS，重组连续数据流
