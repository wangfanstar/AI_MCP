⚡ CtlOS传输优先级详解

同时出现时如何选择：优先收vs优先发的完整指南

CtlOS传输优先级金字塔
优先级 CtlOS类型 发送/处理规则 关键约束
最高
（Level 1）		 LLR_INIT_ECHO • 收到LLR_INIT后立即生成
• 响应式发送，不周期性
• 必须在MAC层中断队列
• 确认就绪状态 		• 绝不延迟
• 最小延迟
• 优先于所有其他消息
中等
（Level 2）		 LLR_INIT • INIT状态周期性发送
• 初始化链接序列
• 容忍丢失（重复发送）
• 4×ctlos_target_spacing周期 		• 可以缓存短期
• 丢失可恢复
• 低于INIT_ECHO
最低

• 速率约束：

- 最慢：每17296字节1个
• ACK和NACK优先级相同
• 不竞争其他消息 		• 可以合并批处理
• 丢失影响重传延迟

• 流控信息

• 不影响LLR状态
• 可被LLR消息抢占
📌 关键概念：优先级定义的是在"同一个物理时刻，MII接口上只能发送一个CtlOS"的情况下，应该优先选择哪一个消息类型。它不是收发的优先级，而是在竞争链路资源时的选择顺序。
同时出现的场景分析
场景1：LLR_INIT_ECHO vs LLR_ACK
同时出现情况：
接收端在处理LLR_INIT时生成LLR_INIT_ECHO，同时ACK计时器也到期需要发送LLR_ACK

时间T： • 收到上游的LLR_INIT → RS层中断 • 本地ACK计时器到期 → MAC层请求发送LLR_ACK • MII接口只有一个8字节的时间窗口 • 优先级：LLR_INIT_ECHO > LLR_ACK
处理规则：
✓ 优先发送LLR_INIT_ECHO
✓ LLR_ACK推迟到下一个ctlos_target_spacing周期
✓ 通常延迟不超过1-2个ctlos_target_spacing
场景2：LLR_INIT vs LLR_NACK
同时出现情况：
处于INIT状态需要周期性发送LLR_INIT，同时检测到帧丢失需要发送LLR_NACK

时间T： • 状态机在INIT状态，LLR_INIT计时器到期 • RX端检测到期望序列号不匹配 → 需要NACK • 两个请求竞争同一个MII时间窗口 • 优先级：LLR_INIT > LLR_NACK
处理规则：
✓ 优先发送LLR_INIT（初始化更重要）
✓ LLR_NACK通过下一个可用的ctlos时间窗口发送
✓ LLR状态机中：if (init_state) { send_init() } else { send_nack_if_pending() }
场景3：LLR_INIT_ECHO vs LLR_NACK
同时出现情况：
接收LLR_INIT需要立即回复INIT_ECHO，同时检测到数据帧序列号错误需要NACK

时间T： • 收到LLR_INIT → RS和MAC层都有请求 • 检测到RXD帧的fcs_status = BAD → 需要NACK • 但LLR_INIT_ECHO优先级更高 • 优先级：LLR_INIT_ECHO >> LLR_NACK
处理规则：
✓ 立即发送LLR_INIT_ECHO（确认初始化）
✓ NACK在INIT_ECHO发送后的ctlos_target_spacing周期内发送
✓ NACK不会因为初始化而丢弃，会在下一个窗口被发出
场景4：LLR_ACK vs CF_Update（CBFC启用时）
同时出现情况：
CBFC和LLR都启用，需要发送CF_Update同时ACK计时器到期

时间T： • CBFC虚拟通道缓冲区达到阈值 → CF_Update待发 • LLR ACK计时器到期 → LLR_ACK待发 • 两个消息竞争MII资源 • 优先级：LLR_ACK > CF_Update
处理规则：
✓ 优先发送LLR_ACK（维护LLR state）
✓ CF_Update使用下一个可用时间窗口
✓ CBFC不会阻塞或延迟LLR消息
ℹ 注意：这里没有"优先收或优先发"的区别，两者都是发送
优先收 vs 优先发的理解误区
⚠️ 常见误解： "优先级是指同时收到和需要发送CtlOS时，应该优先处理哪个操作"

✓ 正确理解： 优先级是指在多个待发送的CtlOS消息中，应该优先选择哪一个发送
ℹ️ 为什么不存在"优先收"？

CtlOS的接收（RX）和发送（TX）是独立的过程：
  • RX（接收）：RS和PCS层自动识别入站CtlOS，无需优先级选择，因为物理层会识别所有O-code=0x6的块
  • TX（发送）：MAC层需要在多个待发CtlOS中选择，这里才存在优先级
  • 接收不需要选择（自动的），所以不存在"优先收"这个概念
具体例子：同时收发
时刻T，设备A和设备B之间的情况：
设备A（发送端）：
• 正在周期性发送LLR_ACK
• 收到来自B的LLR_INIT → 需要立即回复INIT_ECHO
• **优先级判定：** LLR_INIT_ECHO > LLR_ACK
• **操作：** 中断当前LLR_ACK，优先发送LLR_INIT_ECHO

设备B（接收端）：
• 自动接收来自A的LLR_INIT_ECHO（物理层自动处理，无需优先级）
• 自动接收来自A的LLR_ACK（物理层自动处理，无需优先级）
• **无优先级冲突**：两个都能接收
MAC层发送调度的伪代码实现
// CtlOS发送优先级调度（MAC层） function schedule_ctlos_transmission() { // 检查各类型CtlOS的发送条件（按优先级） // Level 1：最高优先级 if (pending_LLR_INIT_ECHO) { MII_output(LLR_INIT_ECHO) pending_LLR_INIT_ECHO = FALSE return // 本周期只发送一个 } // Level 2：中等优先级 if (pending_LLR_INIT && llr_tx_state == INIT && init_timer_expired) { MII_output(LLR_INIT) pending_LLR_INIT = FALSE return } // Level 3：最低优先级 // ACK和NACK优先级相同 if (pending_LLR_NACK) { MII_output(LLR_NACK) pending_LLR_NACK = FALSE nack_transmitted_state = NACK_SENT return } if (pending_LLR_ACK && ack_timer_expired) { MII_output(LLR_ACK) pending_LLR_ACK = FALSE return } // 最低等级：CBFC流控（如启用） if (cbfc_enabled && pending_CF_Update && cf_timer_expired) { MII_output(CF_Update) pending_CF_Update = FALSE return } }
📌 关键约束：
• ctlos_target_spacing约束：最多每400字节发送1个CtlOS，最少每17296字节发送1个
• 8字节对齐到Lane 0
• 不在帧的前256字节内
• 两个CtlOS间距≥400字节
• <2% 链路带宽
LLR/CBFC状态机中的优先级处理
LLR TX状态机CtlOS选择流程
OFF状态： 无CtlOS发送
INIT状态： 周期性发送LLR_INIT（优先级2）
├─ 同时收到LLR_INIT_ECHO_needed
├─ 优先选择：发送LLR_INIT_ECHO（优先级1）
└─ LLR_INIT推迟到下一个ctlos_target_spacing
ADVANCE状态： 发送LLR_ACK（优先级3）
├─ 检测到NACK条件
├─ 优先选择：转到REPLAY状态，发送LLR_NACK（优先级3）
└─ 停止发送ACK
REPLAY状态： 重传数据，发送LLR_NACK if needed
FLUSH状态： 清空缓冲，转INIT或OFF

If credit-based flow control is also active, the CBFC CtlOS should be lowest priority (i.e., below LLR_ACK/LLR_NACK)."
时序约束和发送规则
CtlOS类型 发送条件 周期/速率约束 丢失容忍度
LLR_INIT_ECHO 收到LLR_INIT立即 响应式，无周期 丢失可重传
LLR_INIT INIT状态周期性 ≥ 4×ctlos_target_spacing 丢失可重传
LLR_ACK ADVANCE状态周期 每400B~17296B一次 丢失影响缓冲释放
LLR_NACK 检测到序列号错误 单次，不周期 丢失延迟重传
CF_Update CBFC虚拟通道条件 事件驱动或周期 丢失由CBFC协议处理
⏱️ 标准速率约束（规范5.1.4）：
• 最快速率：最多每400字节发送1个LLR_ACK/NACK
• 最慢速率：最少每17296字节发送1个LLR_ACK/NACK
• 推荐间距：约1600字节（≈0.5%带宽）
• 保证间距：至少400字节

这些约束确保：
✓ 充分的消息频率确保链接伙伴通信
✓ 不过载链接（<2%带宽）
✓ 简化交换机RX CtlOS处理

🎯 关键总结

  • 优先级不是"收vs发"，而是"多个待发消息的选择顺序"：
    • 接收：物理层自动识别所有CtlOS，无需优先级
    • 发送：MAC层需选择哪个CtlOS优先使用MII时间窗口
  • 四级优先级清单：
    • 1️⃣ LLR_INIT_ECHO（最高，确保初始化）
    • 2️⃣ LLR_INIT（初始化周期）
    • 3️⃣ LLR_ACK/NACK（最低，同级）
    • 4️⃣ CF_Update（仅当CBFC启用且LLR无需时）
  • 实现策略：在MAC调度器中按优先级检查pending标志，优先发送高优先级消息
  • 约束条件：遵守ctlos_target_spacing（400B~17296B）、8字节对齐、不在帧前256字节等规则
  • 同时出现时：中断低优先级发送，优先发送高优先级CtlOS，被中断的消息在下一个ctlos窗口发送
