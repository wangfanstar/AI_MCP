📋 MAC Client 层说明

MAC Client 是数据帧的来源。帧在此处被分类为 LLR-eligible（可重传）或 LLR-ineligible（不可重传，如 Pause/PFC 帧）。分类决定了帧在下层的处理方式。

🔄 LLR 引擎关键特性

  • 架构位置：插入在 MAC Client 与 MAC Control 之间，对上层完全透明
  • 非阻塞：LLR 重传期间，MAC Control 仍可发送 Pause/PFC 帧
  • Preamble 嵌入：在前导码中嵌入 0xFB 起始标识 + 20-bit 序列号
  • Poisoning 机制：RAM 不可修复错误时，主动污染 FCS (XOR 0xAAAAAAAA) 防止无限重传

⚡ xMII 总线核心作用

xMII 是 MAC/RS 与 PCS 之间的标准化并行接口，实现物理层无关性。关键特征：

  • 数据 + 控制分离：每个 Lane 同时传输一字节数据(TXD)和一位控制标志(TXC)
  • 控制字符 0x5C：在 Lane 0 表示 LLR CtlOS（控制有序集），PCS 编码为 Block Type 0x4B + O-code 0x6
  • Lane 0 特殊地位：起始分隔符(0xFB)、终止符(0xFD)、有序集均从 Lane 0 发起
  • 速率适配：通过增减 Lane 数和时钟频率支持 1G 到 800G+

🔐 PCS 64B/66B 编码机制

  • 数据块：Sync = 01 + 64-bit 纯数据 → 传输效率 64/66 ≈ 97%
  • 控制块：Sync = 10 + Block Type + 控制信息
  • LLR 关键编码：xMII Lane 0 的 0x5C 控制字符 → PCS Block Type 0x4B，O-code = 0x6
  • FEC：Reed-Solomon RS(544,514) 纠正突发错误，与 LLR 形成双层保护

📡 PMA 子层

PMA 负责将 PCS 编码后的数字信号转换为适合物理介质传输的模拟信号。SerDes 以 112Gbps/lane（PAM4）运行，800G 需要 8 个 Lane。
